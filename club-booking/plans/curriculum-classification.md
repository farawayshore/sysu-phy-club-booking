# 课表专业与班型筛选（本地开发，2026-10-08）

## 已确认的规则

- 用户于 2026-10-09 明确：“物理学类”培养方案仅用于大一课程的判定；大二至大四不得引用该方案作为课程归属或必修/选修性质的依据，应查对应入学届别的专业、班型方案。
- 大一不分专业。大二、大三、大四均独立选择物理学、光信，可同时查看。
- 大二开始有拔尖班；大三另有理论物理国际班；大四继承全部专业与班型选项。用户确认两个特殊班型可同时参加，均为多选，不做互斥处理。
- 不提供“普通班”选项：默认显示基础课表，拔尖班与理论物理国际班默认不勾选，勾选后额外叠加其专属课程和活动。课程性质包括必修、选修、待核对；班级活动独立筛选。
- 课表筛选只影响叠加和冲突提醒，社团预约照常显示；确认课程冲突后仍允许预约。

## 数据与旧数据兼容

保留 version 1、现有表与课程 ID、原日期及两个本地存储 key。Timetable 新增可选 grade（1–4），老数据按年级名称识别。CourseRule 新增可选 category（course/activity）与 audiences。

每条 audience 为 `{major: all|physics|optical, group: all|elite|theory, requirement: required|elective|unknown}`。同一行的专业、班型需同时命中；多行是“或”。一门课可对物理学必修、光信选修。同名不同时间/地点必须创建不同 ID 的规则；一条规则匹配多个班型时不重复显示。

尚未分类的旧规则保持待核对，不推断其归属。当前大三 25 条规则保持时间与地点不变；大一、大二、大四仅为空表入口，不含虚构课程。旧本地存档补充缺失的空年级入口而不覆盖已有内容。培养方案原文件存 `resources/program-plans/`，不参与浏览器或云函数打包；收到后在此记录来源页码与判定。

POST /api/bookings 新增可选 courseFilters，按 table ID 保存 majors/groups/types；前端日历、离线模拟接口、uniCloud 与旧 D1 使用同一匹配函数。缺省字段兼容旧客户端。后端拒绝无效选项，确认签名包含性质与适用范围以避免错误复用。
